# Implementation rules
- Consortium header announcements use the existing capture-exclusion markers, and the white camera preserves the original glyph's footprint so visual changes cannot resize the save control or alter exported layout.
- Consortium image export shares existing clone preparation, then dynamically loads html2canvas only for iOS; other devices retain dom-to-image-more and their existing download path.
- iOS export reserves an image-preview window during the click and offers a fresh-gesture file-share button when asynchronous capture loses Safari user activation; release capture canvases and revoke preview Blob URLs on page close.
- iPad export bypasses asynchronous native sharing until preview display, bounds capture waits and adaptive intermediate memory, and uses temporary Blob preview URLs; this prevents WebKit promises from leaving the preview pending without changing iPhone or non-iOS routines.
- Contact alignment corrections belong only to exported contact styles; preserve the original flex layout on iPhone and the existing iPad/non-iOS styles so visual fixes cannot alter their capture routines or the visible modal.
- iPhone and iPad capture use a desktop-width private viewport and its resulting content height; normalize only html2canvas's baseline-measurement GIF in both the private clone and caller document (CanvasRenderer measures fonts in the latter), removing the caller override when capture settles. Never compensate text with per-cell transforms or rebuild the grid.
- Consortium export retains an 800px CSS clone and caps adaptive capture at final-fit resolution, 7.5MP (4MP on older iOS/low-memory browsers) and 4096px per edge, with lower-scale retries; this improves local sharpness without altering layout.
- Consortium source images set anonymous CORS before src; export validates loaded pixels, keeps cached source URLs for html2canvas and embeds locally rasterized PNGs for dom-to-image-more with cache busting disabled; this avoids explicit duplicate image fetches and intermediate JPEG recompression.
- Android phone exports resolve the existing 800px clone inside a temporary 1280px desktop viewport before dom-to-image-more capture, then remove that viewport; this preserves desktop proportions without changing tablets, iOS, visible modals or download routines.
